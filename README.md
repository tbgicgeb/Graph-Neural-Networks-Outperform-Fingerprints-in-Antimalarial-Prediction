# Graph vs fingerprint models for antimalarial activity prediction

Dataset, code, figures and tables for the manuscript:

> **Graph neural networks outperform fingerprint models for predicting antimalarial
> activity of structurally novel compounds: a systematic out-of-distribution benchmark**

Four models â€” **Random Forest**, **XGBoost**, **ChemProp** (D-MPNN) and
**GNEprop** (GIN) â€” are compared on 27,493 *Plasmodium falciparum* screening
compounds, under three ways of splitting the data and in two settings each
(default settings and hyperparameter-tuned).

**Main result.** On the hardest split â€” where test compounds come from chemical
neighbourhoods the model has never seen â€” the two graph models outperformed the two
fingerprint models by **+0.041 AUPRC** (7 of 8 folds, paired *t* *p* = 0.007).

## The three splits

Every model is run on all three. They get progressively harder, which is the
point of the study.

| Split | How test compounds are chosen | How similar test is to training |
|---|---|---|
| **Random** | at random | mean Tanimoto 0.581 â€” 34.8% of test actives have a near-duplicate in training |
| **Scaffold** | whole Bemisâ€“Murcko scaffolds held out | 0.510 â€” 17.5% near-duplicates |
| **Scaffold-cluster** | whole clusters of related scaffolds held out | 0.402 â€” 3.0% near-duplicates |

Scaffold-cluster is the out-of-distribution benchmark and the one the headline
numbers come from. Splits are fixed (seed 42), so everyone gets the same folds.

## The two settings

| Setting | What it means |
|---|---|
| **Default** | each model run out of the box, with the library's own defaults |
| **Tuned** | hyperparameters searched for each model, then the best configuration used |

Both settings are reported, because the comparison changes between them: at
default settings the four models look alike, and the graph advantage only
appears once every model has been properly tuned.

Random Forest and XGBoost run on a normal CPU. ChemProp and GNEprop need a

want different versions of PyTorch.

### Environment 1 â€” fingerprint models, figures and tables

## The code, step by step

Run in this order. Stages 1â€“4 are only needed if you want to rebuild the
results from scratch; the results are already in `results/`, so stage 5 works
on its own.

Both the folders and the scripts inside them are numbered, so the order you
see in the folder **is** the order you run them in.

### 1. Dataset and splits â€” `code/1_data/`

| Script | What it does |
|---|---|
| `01_prepare_dataset.py` | curates the dataset and computes descriptors |
| `02_make_splits.py` | builds the random, scaffold and scaffold-cluster 8-fold splits |
| `03_check_split_similarity.py` | measures how similar test compounds are to training |

### 2. Models at default settings â€” `code/2_models_default/`

Each script covers all three splits.

| Script | Models |
|---|---|
| `01_random_forest_and_xgboost.py` | Random Forest, XGBoost (CPU) |
| `02_chemprop.py` | ChemProp (GPU) |
| `03_gneprop.py` | GNEprop (GPU) |

### 3. Models after hyperparameter tuning â€” `code/3_models_tuned/`

| Script | Model and search |
|---|---|
| `01_random_forest.py` | 50 Optuna trials per fold, nested 3-fold inner CV |
| `02_xgboost.py` | same protocol |
| `03_chemprop.py` | per-fold search on a scaffold-disjoint inner validation set |
| `04_chemprop_random_and_scaffold_splits.py` | the tuned ChemProp on the two easier splits |
| `05_gneprop.py` | configuration chosen on fold-0 validation score, applied to all folds |

### 4. Extra analyses â€” `code/4_analysis/`

Prediction exports first, because the ensembles and several figures read them;

| Script | What it does |
|---|---|
| `01`â€“`05_export_predictions_*.py` | writes per-compound held-out predictions for all four models, default and tuned |
| `06`â€“`09_*_ensemble_*.py` | the 2- and 3-model ChemProp and GNEprop ensembles (Table 2, Figure 5) |
| `10_gneprop_extra_search.py` | the wider GNEprop search reported in the supplement |
| `11`â€“`12_learning_curve_*.py` | learning curves for all four models (Figure 7) |
| `13_collect_results.py` | gathers every per-fold result into `results/MASTER_*.csv` |

### 5. Figures and tables â€” `code/5_figures_and_tables/`
